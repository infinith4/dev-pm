## 1. 概要

| 項目 | 内容 |
|------|------|
| アクター | 店舗スタッフ（ショップ管理者またはスタッフ）、Entra ID テナント（テナント専用） |
| 目的 | テナント専用の Entra ID テナントを使用した OIDC SSO で管理サイトにログインし、ロールに応じたダッシュボードを表示する |
| スコープ | テナント専用管理サイト（`admin.{顧客ドメイン}`） |
| レベル | ユーザーゴール |
| 頻度 | 日次（テナントあたり 1〜50 名のスタッフが利用） |

---

## 2. 事前条件

- テナントが管理サイトを利用可能な状態（テナント状態: `active`）
- テナント専用の Entra ID テナントが自動プロビジョニング済み
- 管理サイト用 OIDC アプリ（`ShopHub.Admin` ロール定義含む）が Entra ID テナントに登録済み
- 店舗スタッフのアカウントがテナントの Entra ID テナントに存在し、`ShopHub.Admin` または `ShopHub.Staff` ロールが付与されている

---

## 3. 事後条件

**成功時**:
- 店舗スタッフが管理サイトにログインし、ロールに応じたダッシュボードが表示される
  - `ShopHub.Admin`（ショップ管理者）: 商品管理・注文管理・在庫管理・スタッフ管理・バッチ状況・工場設定へのフルアクセス
  - `ShopHub.Staff`（スタッフ）: 注文管理・在庫更新への制限アクセス
- セッション（JWT アクセストークン: 1 時間、リフレッシュトークン: 30 日）が確立される
- セッションにテナント ID が紐付けられ、他テナントのリソースにはアクセスできない

**失敗時**:
- ログインエラーメッセージが表示される
- セッションは確立されない

---

## 4. トリガー

店舗スタッフが管理サイト URL（`admin.myshop.jp`）にアクセスした

---

## 5. 正常フロー（Entra ID OIDC フロー）

| ステップ | 店舗スタッフの操作 | システムの動作 |
|---------|---------------|------------|
| 1 | 管理サイト URL（`https://admin.myshop.jp`）にアクセス | Azure Front Door がホスト名からテナント A を識別 |
| 2 | — | 管理サイトが未認証を検知し、テナント A の Entra ID テナントの OIDC 認証エンドポイントへリダイレクト（`https://login.microsoftonline.com/{テナントAのEntraID-tenant-id}/v2.0`） |
| 3 | Entra ID のログインページが表示される。メールアドレスを入力 | Entra ID がアカウントを確認し、パスワード入力を要求 |
| 4 | パスワードを入力 | Entra ID がパスワードを検証 |
| 5 | MFA 認証を実行（Authenticator アプリ通知承認 / TOTP コード入力） | Entra ID 条件付きアクセスポリシーに基づいて MFA を要求 |
| 6 | MFA 承認 | Entra ID が認可コードを管理サイトへ返す（OIDC Authorization Code フロー） |
| 7 | — | 管理サイトバックエンドが認可コードを使って Entra ID のトークンエンドポイントに ID トークン・アクセストークン・リフレッシュトークンをリクエスト |
| 8 | — | **JWT iss クレーム検証**: 受信した JWT の `iss`（`https://login.microsoftonline.com/{テナントAのEntraID-tenant-id}/v2.0`）がリクエストのテナント A の Entra ID テナント ID と一致することを検証（BR-MT-22）。不一致の場合は認証失敗（HTTP 401）。 |
| 9 | — | JWT の `roles` クレームからロール（`ShopHub.Admin` / `ShopHub.Staff`）を取得 |
| 10 | — | テナント A のセッションを確立（Redis にセッションデータを保存）。セッションにテナント ID・ユーザー ID・ロールを紐付け |
| 11 | 管理サイトのダッシュボードが表示される | ロールに応じたダッシュボードを表示:  **ShopHub.Admin**: 注文数・売上・在庫アラート・夜間バッチ実行状況・工場転送状況のサマリー。  **ShopHub.Staff**: 注文管理・在庫更新のショートカット。 |
| 12 | — | Entra ID サインインログを Azure Monitor に記録（テナント ID・ユーザー ID・ログイン時刻・IP アドレス） |

## 6. 代替フロー

### 代替フロー A: リフレッシュトークンによる自動再認証

| ステップ | 説明 |
|---------|------|
| A-1 | アクセストークン（有効期限 1 時間）が期限切れになる |
| A-2 | クライアントが自動的にリフレッシュトークン（有効期限 30 日）を使用して新しいアクセストークンをリクエスト |
| A-3 | 店舗スタッフはログアウトを意識せずに操作を継続できる |

### 代替フロー B: 既にログイン済みのケース

| ステップ | 説明 |
|---------|------|
| B-1 | 店舗スタッフが管理サイトにアクセスし、有効なセッション（アクセストークン）が存在する |
| B-2 | 管理サイトは Entra ID への再認証をスキップし、直接ダッシュボードを表示 |

## 7. 例外フロー

### 例外 E-1: ロールが付与されていない（権限不足）

| 条件 | JWT の `roles` クレームに `ShopHub.Admin` も `ShopHub.Staff` も含まれない |
|------|------|
| システムの動作 | HTTP 403 Forbidden を返し、「このアカウントは管理サイトへのアクセス権限がありません。テナント管理者にお問い合わせください」を表示 |
| 事後状態 | セッションは確立されない |

### 例外 E-2: JWT iss クレーム不一致（Entra ID テナント分離違反）

| 条件 | テナント B の Entra ID アカウントでテナント A の管理サイトにアクセス |
|------|------|
| システムの動作 | JWT の `iss` クレームとリクエストのテナント A の Entra ID テナント ID が不一致 → HTTP 401 を返す。Azure Monitor にセキュリティアラートを記録（BR-MT-22） |
| 事後状態 | セッションは確立されない。プラットフォーム管理者に通知 |

### 例外 E-3: MFA 失敗

| 条件 | MFA 認証を 3 回失敗 |
|------|------|
| システムの動作 | Entra ID がアカウントをロックアウト（条件付きアクセスポリシーに従う）。エラーメッセージを表示 |
| 事後状態 | テナント管理者によるアカウントロック解除が必要 |

### 例外 E-4: テナントが停止中

| 条件 | テナント状態が `suspended` または `payment_suspended` |
|------|------|
| システムの動作 | ログインを拒否し「サービスが一時停止されています。プラットフォーム管理者へお問い合わせください」を表示 |
| 事後状態 | セッションは確立されない |

### 例外 E-5: Entra ID への接続失敗

| 条件 | Microsoft Entra ID サービスが一時的に利用不可 |
|------|------|
| システムの動作 | 「認証サービスが一時的に利用できません。しばらく後にお試しください」を表示 |
| 事後状態 | セッションは確立されない。Azure Monitor にアラートを記録 |

## 8. ダッシュボード表示内容（ロール別）

### ShopHub.Admin（ショップ管理者）ダッシュボード

| セクション | 表示内容 |
|---------|---------|
| 今日の注文サマリー | 本日の注文数・売上合計・キャンセル数 |
| 在庫アラート | 在庫数が閾値（10 個以下）を下回った商品一覧 |
| 夜間バッチ状況 | 昨日のバッチ実行結果（処理件数・完了時刻・エラー件数）・本日のバッチ予定時刻（22:00） |
| 工場転送状況 | 昨日の工場別転送結果（ファイル名・件数・転送完了時刻・ステータス） |
| クイックリンク | 商品管理・注文管理・スタッフ管理・工場設定・バッチ詳細 |

### ShopHub.Staff（スタッフ）ダッシュボード

| セクション | 表示内容 |
|---------|---------|
| 本日の注文 | 未処理注文一覧（注文番号・商品・配送先・ステータス） |
| 在庫更新 | 商品在庫の更新ショートカット |
| クイックリンク | 注文管理・在庫管理 |

## 9. 補足情報

- **Entra ID テナント分離**: テナント A の管理サイトはテナント A 専用の Entra ID テナントの JWT のみを受け入れる。JWT の `iss` クレームによる厳格なテナント検証が行われる（BR-MT-22）
- **MFA の設定**: テナント管理者はテナントの Entra ID テナントの条件付きアクセスポリシーで MFA の要求条件を設定できる（例: 社外 IP アドレスからのアクセス時のみ MFA 要求）
- **バッチ状況の確認**: `ShopHub.Admin` ロールを持つショップ管理者は、管理サイトのダッシュボードで夜間バッチの実行状況（処理件数・進捗率・完了時刻・工場転送状況）を確認できる
