## 1. 概要

FR-021（工場データ連携）でデータを受け取った工場は、数時間後に出荷準備が完了したタイミングで ShopHub SaaS に出荷完了通知を送信する。本機能要件は、その通知を安全に受信・検証し、該当注文のステータスを `shipped` に更新し、消費者および店舗スタッフへ発送通知を送信するまでの一連の処理を定義する。

**関連**:
- FR-021（工場データ連携）からの受信側フロー
- FR-001（EC サイト）─ 注文ステータス管理
- BR-FACTORY-11〜BR-FACTORY-15
- UC-004（工場から出荷完了通知を受信する）
- US-021（工場から出荷完了通知を受け取る）

## 2. 機能要件

### 2.1 ShipNotify.Endpoint: 出荷完了通知受信エンドポイント

**ShipNotify.Endpoint.Register: エンドポイントの登録**

**.Url**: システムは、工場ごとに一意の出荷完了通知受信 URL（Webhook エンドポイント）を発行しなければならない。URL 形式は `/api/v1/factories/{factory_id}/ship-notify` とする。（BR-FACTORY-11 参照）

**.Auth**: エンドポイントは HTTPS のみを受け付けなければならない。工場システムからのリクエストは、Azure API Management（APIM）を通して受け付け、HMAC-SHA256 署名検証を必須とする。（BR-FACTORY-12 参照）

**.HmacKey**: 各工場の HMAC 署名キーは、工場マスタ登録時に自動生成し Azure Key Vault に保存しなければならない。キーをレスポンスやログに平文で出力してはならない。（BR-FACTORY-12 参照）

**.NotifyUrl**: テナント管理者は、管理サイトの工場マスタ画面から通知受信 URL と HMAC キーを確認・再発行できなければならない。

---

### 2.2 ShipNotify.Receive: 通知受信・検証

**ShipNotify.Receive.Validate: リクエスト検証**

**.Schema**: システムは、受信した JSON ペイロードが以下のスキーマに準拠することを検証しなければならない。スキーマ不正の場合は HTTP 400 を返す:

```json
{
  "factory_code": "string（必須）",
  "tenant_id": "string（必須）",
  "shipped_orders": [
    {
      "order_id": "string（必須）",
      "shipped_at": "ISO 8601 日時（必須）",
      "tracking_number": "string（任意）",
      "carrier": "string（任意）"
    }
  ]
}
```

**.HmacVerify**: システムは、リクエストヘッダー `X-ShopHub-Signature` の HMAC-SHA256 値を工場マスタの HMAC キーで検証しなければならない。署名不一致の場合は HTTP 401 を返し、処理を中断する。（BR-FACTORY-12 参照）

**.TenantVerify**: システムは、ペイロードの `tenant_id` が URL パスの `factory_id` に紐づくテナントと一致することを検証しなければならない。不一致の場合は HTTP 403 を返す。（BR-FACTORY-13 参照）

**.IdempotencyCheck**: システムは、同一 `order_id` の通知を二重に受け付けてはならない。すでに `shipped` 状態の注文に対する通知はスキップし、HTTP 200 を返す（冪等性保証）。（BR-FACTORY-14 参照）

**.RateLimiting**: エンドポイントは工場ごとに 1 分あたり 100 リクエストのレート制限を設ける。超過した場合は HTTP 429 を返す。

---

### 2.3 ShipNotify.Update: 注文ステータス更新

**ShipNotify.Update.Status: 注文ステータスの更新**

**.ShipStatus**: 検証が成功した場合、システムは `shipped_orders` に含まれる各 `order_id` の注文ステータスを `shipped` に更新しなければならない。（BR-FACTORY-15 参照）

**.TrackingInfo**: 更新時に `tracking_number`（追跡番号）と `carrier`（配送業者）が含まれる場合、`order_shipping_info` テーブルに記録しなければならない。

**.Timestamp**: 注文テーブルの `shipped_at` カラムにペイロードの `shipped_at` 日時を記録しなければならない。

**.NotFound**: `order_id` が存在しない、またはテナントに属さない注文の場合は該当行をスキップし、スキップした `order_id` 一覧をレスポンスに含める。

**.PartialSuccess**: 複数の注文を含む通知で一部が更新失敗した場合も、成功した注文は確定させる。レスポンスに成功・失敗の内訳を返す。

---

### 2.4 ShipNotify.ConsumerAlert: 消費者への発送通知

**ShipNotify.ConsumerAlert.Email: 発送通知メール**

**.SendEmail**: 注文ステータスが `shipped` に更新されると、システムは消費者のメールアドレスに発送通知メールを送信しなければならない。（BR-FACTORY-15 参照）

**.EmailContent**: 発送通知メールには以下の情報を含めなければならない:
  - テナントのブランド名・ロゴ
  - 注文番号
  - 出荷日時
  - 追跡番号（存在する場合）
  - 配送業者名（存在する場合）
  - 注文した商品一覧（商品名・数量）
  - 配送先住所

**.EmailTemplate**: メールテンプレートはテナントごとにカスタマイズ可能とする。テンプレート未設定の場合はデフォルトテンプレートを使用する。

**.NoEmail**: ゲスト購入で消費者メールアドレスが存在しない場合はメール送信をスキップし、ログに記録する。

---

### 2.5 ShipNotify.StaffAlert: 店舗スタッフへの通知

**ShipNotify.StaffAlert.Dashboard: 管理サイトへの反映**

**.OrderList**: 注文ステータスの更新はリアルタイムで管理サイトの注文一覧に反映しなければならない。

**.Notification**: 管理サイトにログイン中の店舗スタッフに、出荷完了の通知バナーをリアルタイム表示しなければならない（WebSocket または Server-Sent Events）。

---

### 2.6 ShipNotify.Log: 受信ログ記録

**ShipNotify.Log.Record: 通知受信ログ**

**.Log**: システムは、通知受信ごとに以下の項目を `ship_notify_logs` テーブルに記録しなければならない:
  - 通知ログ ID（UUID）
  - 工場 ID
  - テナント ID
  - 受信日時
  - 受信件数（`shipped_orders` の件数）
  - 成功件数 / スキップ件数 / エラー件数
  - HTTP レスポンスコード
  - エラーメッセージ（失敗時）

**.AdminView**: テナント管理者は、管理サイトで直近 30 日間の出荷完了通知受信ログ（工場別・日別）を確認できなければならない。

---

### 2.7 ShipNotify.Retry: エラー時の工場への再送指示

**ShipNotify.Retry.Guide: 工場への再送ガイダンス**

**.ErrorResponse**: HTTP 5xx エラーが発生した場合、システムは工場システムが再送できるよう `Retry-After` ヘッダーに待機秒数を含めなければならない。

**.AlertOnRecurring**: 同一工場から 1 時間以内に 10 件以上の失敗通知が発生した場合、テナント管理者にアラートメールを送信しなければならない。

## 3. 工場出荷完了通知フロー

```
工場システム（出荷完了後、数時間後）
    │ HTTPS POST /api/v1/factories/{factory_id}/ship-notify
    │ ヘッダー: X-ShopHub-Signature: HMAC-SHA256(payload, hmac_key)
    │
    ▼
[1] ShipNotify.Endpoint: Azure APIM でリクエスト受信
    │
    ▼
[2] ShipNotify.Receive.Validate: スキーマ検証
    │（不正: HTTP 400）
    ▼
[3] ShipNotify.Receive.HmacVerify: HMAC-SHA256 署名検証
    │（不一致: HTTP 401）
    ▼
[4] ShipNotify.Receive.TenantVerify: テナント・工場の対応確認
    │（不一致: HTTP 403）
    ▼
[5] ShipNotify.Receive.IdempotencyCheck: 二重受信チェック
    │（既処理: スキップして HTTP 200）
    ▼
[6] ShipNotify.Update.Status: 注文ステータスを shipped に更新
    │（追跡番号・配送業者も記録）
    ▼
[7] ShipNotify.ConsumerAlert.Email: 消費者に発送通知メール送信
    ▼
[8] ShipNotify.StaffAlert.Dashboard: 管理サイトにリアルタイム反映
    ▼
[9] ShipNotify.Log.Record: 受信ログ記録
    ▼
HTTP 200 レスポンス（成功・スキップ件数を含む）
```

**レスポンス例（HTTP 200）**:

```json
{
  "received_at": "2026-12-02T10:30:00+09:00",
  "total": 3,
  "succeeded": 2,
  "skipped": 1,
  "failed": 0,
  "skipped_order_ids": ["myshop-20261201-00000003"]
}
```

## 4. データモデル追加（Tenant DB）

### 4.1 orders テーブル 追加カラム

| フィールド | 型 | 制約 | 説明 |
|---------|----|----|------|
| shipped_at | TIMESTAMPTZ | NULL 可 | 工場からの出荷完了日時（ペイロードの shipped_at） |

### 4.2 order_shipping_info テーブル（新規）

| フィールド | 型 | 制約 | 説明 |
|---------|----|----|------|
| shipping_id | UUID | PK, NOT NULL | 出荷情報一意識別子 |
| order_id | UUID | FK, NOT NULL | 注文 ID |
| factory_id | UUID | FK, NOT NULL | 通知元工場 ID |
| tracking_number | VARCHAR(100) | NULL 可 | 追跡番号 |
| carrier | VARCHAR(100) | NULL 可 | 配送業者名 |
| notified_at | TIMESTAMPTZ | NOT NULL | 工場からの通知受信日時 |

### 4.3 ship_notify_logs テーブル（新規）

| フィールド | 型 | 制約 | 説明 |
|---------|----|----|------|
| notify_log_id | UUID | PK, NOT NULL | 通知ログ一意識別子 |
| factory_id | UUID | FK, NOT NULL | 工場 ID |
| tenant_id | UUID | NOT NULL | テナント ID |
| received_at | TIMESTAMPTZ | NOT NULL | 受信日時 |
| total_count | INTEGER | NOT NULL | 受信件数 |
| success_count | INTEGER | NOT NULL | 更新成功件数 |
| skip_count | INTEGER | NOT NULL | スキップ件数（既処理） |
| error_count | INTEGER | NOT NULL | エラー件数 |
| http_status | SMALLINT | NOT NULL | HTTP レスポンスコード |
| error_message | TEXT | NULL 可 | エラーメッセージ |

### 4.4 factory_masters テーブル 追加カラム（Platform DB）

| フィールド | 型 | 制約 | 説明 |
|---------|----|----|------|
| ship_notify_enabled | BOOLEAN | NOT NULL, DEFAULT true | 出荷完了通知受信の有効/無効 |
| ship_notify_hmac_key_vault_ref | VARCHAR(500) | NULL 可 | HMAC キーの Key Vault 参照名 |
