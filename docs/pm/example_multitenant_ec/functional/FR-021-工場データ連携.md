## 1. 概要

夜間バッチ（FR-020）で生成された変換済み CSV ファイルを、工場マスタの設定に基づいて工場ごとの SFTP サーバーまたは Azure Blob に配布する。工場ごとに異なる CSV フォーマット・転送方式・認証情報・通知設定に対応し、転送ログを記録する。転送失敗時は自動リトライ後にアラートを発報する。

**関連**:
- FE-7（工場データ連携）
- BR-FACTORY-01〜BR-FACTORY-10
- UC-003（夜間バッチで工場にデータを送信する）
- US-020（夜間バッチで注文データを工場に送る）
- FR-020（夜間バッチ処理）からの引き渡し

## 2. 機能要件

### 2.1 Factory.FormatMaster: 工場マスタ管理

**Factory.FormatMaster.CRUD: 工場マスタの登録・更新・削除**

**.Add**: テナント管理者は、管理サイトから以下の項目を入力して工場を登録できなければならない:
  - 工場コード（テナント内で一意、英数字とハイフンのみ、最大 20 文字）
  - 工場名（最大 200 文字）
  - フォーマット定義（新規作成または既存の定義から選択）
  - 転送方式（SFTP または Azure Blob）
  - SFTP 接続情報（ホスト名・ユーザー名・SSH 秘密鍵）または Blob URI
  - PGP 暗号化の要否（PGP 公開鍵）
  - 通知設定（Webhook URL / メールアドレス / なし）

**.Update**: テナント管理者は、登録済みの工場設定を更新できなければならない。（BR-FACTORY-10 参照）

**.Delete**: テナント管理者は、工場を削除できなければならない。削除後はその工場向けの夜間バッチ処理が停止される。

**.Test**: テナント管理者は、工場設定登録後に接続テスト（SFTP 接続確認または Blob アクセス確認）を実行できなければならない。

### 2.2 Factory.FormatDef: フォーマット定義管理

**Factory.FormatDef.Define: フォーマット定義の作成**

**.Create**: テナント管理者は、工場ごとのフォーマット定義を管理画面から作成できなければならない。フォーマット定義には以下の項目を含める:（BR-FACTORY-01 参照）
  - 定義名（例: "工場A標準フォーマット v2"）
  - エンコーディング（UTF-8 / Shift_JIS / EUC-JP から選択）
  - 区切り文字（カンマ / タブ / パイプ から選択）
  - ヘッダー行の有無
  - ファイル拡張子（csv / tsv）
  - 列定義一覧（列インデックス・列名・型・必須・マッピングソース・変換書式）

**.ColumnTypes**: システムは以下の列型をサポートしなければならない:
  - `string`: 文字列（トリム・最大長指定可）
  - `integer`: 整数
  - `decimal`: 小数（小数点桁数指定可）
  - `date`: 日付（出力フォーマット指定可：`yyyyMMdd` / `yyyy/MM/dd` / `yyyy-MM-dd` 等）
  - `datetime`: 日時（出力フォーマット指定可）

**.MappingSource**: システムは以下のマッピングソースをサポートしなければならない:
  - `order_id`: 注文番号
  - `ordered_at`: 注文日時
  - `product_code`: 商品コード
  - `product_name`: 商品名
  - `quantity`: 数量
  - `unit_price`: 単価
  - `total_amount`: 合計金額
  - `consumer_name`: 消費者氏名
  - `shipping_postal_code`: 配送先郵便番号
  - `shipping_address`: 配送先住所（都道府県+市区町村+番地+建物名）
  - `tenant_id`: テナント ID（固定値として埋め込み）
  - `constant:{value}`: 固定値

**フォーマット定義サンプル（工場 A）**:

```json
{
  "format_def_id": "fdf-001",
  "name": "工場A標準フォーマット v2",
  "encoding": "Shift_JIS",
  "delimiter": ",",
  "has_header": true,
  "file_extension": "csv",
  "columns": [
    {"col_index": 1, "col_name": "受注番号",   "type": "string",  "required": true,  "source": "order_id"},
    {"col_index": 2, "col_name": "受注日",     "type": "date",    "required": true,  "source": "ordered_at", "format": "yyyyMMdd"},
    {"col_index": 3, "col_name": "商品コード", "type": "string",  "required": true,  "source": "product_code"},
    {"col_index": 4, "col_name": "商品名",     "type": "string",  "required": true,  "source": "product_name"},
    {"col_index": 5, "col_name": "数量",       "type": "integer", "required": true,  "source": "quantity"},
    {"col_index": 6, "col_name": "単価",       "type": "decimal", "required": false, "source": "unit_price", "decimal_places": 0},
    {"col_index": 7, "col_name": "配送先",     "type": "string",  "required": true,  "source": "shipping_address"},
    {"col_index": 8, "col_name": "テナントID", "type": "string",  "required": true,  "source": "tenant_id"}
  ]
}
```

### 2.3 Factory.Generate: CSV/TSV 生成

**Factory.Generate.Convert: フォーマット変換**

**.FromBatch**: システムは、FR-020（夜間バッチ処理）が Azure Blob に保存した注文データを受け取り、工場マスタのフォーマット定義に基づいて CSV/TSV に変換しなければならない。

**.PerFactory**: システムは、テナントに設定された工場ごとに個別のファイルを生成しなければならない。同一注文データを複数のフォーマット定義で変換し、工場ごとに異なるファイルを生成できなければならない。

**.FileName**: 生成するファイル名は `{工場コード}_{テナントID}_{YYYYMMDD}_{連番2桁}.csv` の形式とする（例: `FACTORY-A_tenant-001_20261201_01.csv`）。（BR-FACTORY-03 参照）

**出力 CSV サンプル（工場 A: Shift_JIS・カンマ区切り・ヘッダーあり）**:

```
受注番号,受注日,商品コード,商品名,数量,単価,配送先,テナントID
myshop-20261201-00000001,20261201,SKU-001,商品A,3,1500,東京都新宿区西新宿1-1-1,tenant-001
myshop-20261201-00000002,20261201,SKU-002,商品B,1,3000,大阪府大阪市北区梅田1-2-3 梅田ビル101,tenant-001
myshop-20261201-00000003,20261201,SKU-001,商品A,2,1500,愛知県名古屋市中村区名駅1-1-1,tenant-001
```

**出力 CSV サンプル（工場 B: UTF-8・タブ区切り・ヘッダーなし）**:

```
myshop-20261201-00000001	20261201	SKU-001	3	1500
myshop-20261201-00000002	20261201	SKU-002	1	3000
myshop-20261201-00000003	20261201	SKU-001	2	1500
```

### 2.4 Factory.Encrypt: PGP 暗号化

**Factory.Encrypt.PGP: PGP 暗号化処理**

**.Encrypt**: 工場マスタで `use_pgp = true` が設定されている場合、システムは CSV ファイルを工場の PGP 公開鍵で暗号化してから転送しなければならない。（BR-FACTORY-06 参照）

**.KeyVault**: PGP 公開鍵は Azure Key Vault に保存し、暗号化処理時に取得しなければならない。PGP 鍵をコードや Blob に保存してはならない。

**.Extension**: 暗号化後のファイル拡張子は `.csv.gpg` とする（例: `FACTORY-A_tenant-001_20261201_01.csv.gpg`）。

---

### 2.5 Factory.Transfer.SFTP: SFTP 転送

**Factory.Transfer.SFTP.Connect: SFTP 接続**

**.SSHKey**: システムは、SSH キー認証を使用して SFTP サーバーに接続しなければならない。パスワード認証を使用してはならない。（BR-FACTORY-07 参照）

**.KeyVault**: SSH 秘密鍵は Azure Key Vault に保存し、接続時に取得しなければならない。秘密鍵をコードや Blob に保存してはならない。（BR-FACTORY-07 参照）

**.Transfer**: システムは、ファイルを SFTP の指定ディレクトリに転送しなければならない。転送は TempFile パターン（一時ファイル名 + リネーム）で実装し、工場側が不完全なファイルを読まないようにしなければならない。

**.Verify**: システムは、転送後にリモートファイルのサイズをローカルと照合し、一致しない場合は転送失敗として扱わなければならない。

---

### 2.6 Factory.Transfer.Blob: Azure Blob 配置

**Factory.Transfer.Blob.Upload: Blob への配置**

**.Upload**: 転送方式が `blob` の場合、システムは工場マスタの `blob_uri` で指定された Azure Blob Storage コンテナにファイルを配置しなければならない。

**.SASNotify**: ファイル配置後、システムは工場の通知設定（Webhook / メール）に SAS URL（有効期限 7 日間）を含めて通知しなければならない。

---

### 2.7 Factory.TransferLog: 転送ログ記録

**Factory.TransferLog.Record: 転送結果の記録**

**.Log**: システムは、ファイル転送ごとに以下の項目を `transfer_logs` テーブルに記録しなければならない。（BR-FACTORY-04 参照）:
  - 転送ログ ID（UUID）
  - テナント ID
  - 工場 ID
  - ファイル名
  - ファイルサイズ（バイト）
  - 転送件数（行数）
  - 転送方式（sftp / blob）
  - 転送先（SFTP ホスト名 / Blob URI）
  - ステータス（success / failed / retry）
  - 完了時刻（TIMESTAMPTZ）
  - エラーメッセージ（失敗時）

**.AdminView**: テナント管理者は、管理サイトで当日・直近 30 日間の転送ログ（工場別・日別）を確認できなければならない。

---

### 2.8 Factory.Notify: 工場システムへの転送完了通知

**Factory.Notify.Webhook: Webhook 通知**

**.Webhook**: 工場マスタの `notify_type = webhook` の場合、システムは転送完了後に工場の Webhook URL へ HTTP POST リクエストを送信しなければならない。（BR-FACTORY-08 参照）

**.WebhookPayload**: Webhook のペイロードには以下の項目を含めなければならない:
```json
{
  "event": "file_transferred",
  "factory_code": "FACTORY-A",
  "tenant_id": "tenant-001",
  "file_name": "FACTORY-A_tenant-001_20261201_01.csv",
  "record_count": 1234,
  "transferred_at": "2026-12-02T03:30:00+09:00",
  "transfer_type": "sftp"
}
```

**Factory.Notify.Email: メール通知**

**.Email**: 工場マスタの `notify_type = email` の場合、システムは転送完了後に工場担当者のメールアドレスへ転送完了メールを送信しなければならない。（BR-FACTORY-08 参照）

**.EmailContent**: メールには工場名・ファイル名・件数・転送完了時刻・SAS URL（Blob 転送の場合）を含めなければならない。

---

### 2.9 Factory.Retry: 転送失敗時のリトライ

**Factory.Retry.Auto: 自動リトライ処理**

**.RetryPolicy**: システムは、ファイル転送が失敗した場合、指数バックオフ（1 分後・2 分後・4 分後）で最大 3 回自動リトライしなければならない。（BR-FACTORY-05 参照）

**.AlertOnFail**: 3 回リトライ後も失敗した場合、システムはプラットフォーム管理者とテナント管理者にアラートメールを送信しなければならない。メール内容には工場名・ファイル名・エラー内容・手動再転送手順を含める。（BR-FACTORY-05 参照）

**.ManualRetransfer**: プラットフォーム管理者は、転送失敗となったファイルを管理画面から手動で再転送できなければならない。

## 3. 工場データ連携フロー

```
FR-020（夜間バッチ処理）から引き渡し
    │ Azure Service Bus にジョブメッセージを投入
    │ メッセージ: {tenant_id, batch_date, factory_id, blob_path}
    │
    ▼
[1] Factory.FormatMaster: 工場マスタから設定を取得
    │（工場コード・フォーマット定義 ID・転送方式・接続情報・通知設定）
    │
    ▼
[2] Factory.FormatDef: フォーマット定義を取得
    │（列定義・エンコーディング・区切り文字・ヘッダー有無）
    │
    ▼
[3] FR-020 Blob から変換済みデータを読み込む
    │
    ▼
[4] Factory.Generate: フォーマット定義に基づいて CSV/TSV を生成
    │ ファイル名: FACTORY-A_tenant-001_20261201_01.csv
    │
    ▼
[5] Factory.Encrypt: PGP 暗号化（use_pgp = true の場合のみ）
    │
    ▼
[6a] Factory.Transfer.SFTP: SFTP サーバーへ転送（SSH キー認証）
     または
[6b] Factory.Transfer.Blob: Azure Blob へ配置（SAS URL 発行）
    │
    ▼
[7] Factory.TransferLog: 転送結果をログに記録
    │
    ▼
[8] Factory.Notify: 転送完了通知（Webhook / メール）
    │
    │ 失敗の場合 ──→ Factory.Retry（最大 3 回）──→ アラート発報
    ▼
転送完了
```

## 4. 工場ごとのフォーマット対応例

| 工場 | エンコーディング | 区切り文字 | ヘッダー | PGP | 転送方式 | 通知 |
|-----|------------|--------|------|-----|------|-----|
| 工場 A（国内大手） | Shift_JIS | カンマ | あり | なし | SFTP | メール |
| 工場 B（海外協力工場） | UTF-8 | タブ | なし | あり（.csv.gpg） | SFTP | Webhook |
| 工場 C（グループ会社） | UTF-8 | カンマ | あり | なし | Azure Blob | Webhook |
| 工場 D（小規模工場） | Shift_JIS | パイプ | あり | なし | SFTP | なし |
