## 2. ステークホルダー詳細プロファイル

### SH-01: 事業部長（スポンサー）

| 項目 | 内容 |
|------|------|
| 姓名（例） | 鈴木 一郎 |
| 組織 | EC 事業部 |
| 主な関心事 | ARR ¥200M（Year 1）達成・インフラコスト削減（¥120,000 → ¥40,000/月）・Release 1 期日（2026-11-30）遵守 |
| 懸念事項 | 投資対効果・競合他社との差別化・バッチ障害による顧客信頼の毀損 |
| コミュニケーション方法 | 月次 Executive Report・マイルストーンレビュー |
| 意思決定権 | 予算・スコープ変更の最終承認 |

### SH-02: プラットフォーム管理者（SaaS 事業者側）

| 項目 | 内容 |
|------|------|
| 組織 | SaaS プラットフォーム運用チーム（約 3 名） |
| 主な関心事 | 全テナントの安定運用・バッチ監視ダッシュボード・Entra ID テナント増加による運用負荷の最小化・工場転送失敗の早期検知 |
| 懸念事項 | バッチ障害時の影響範囲・工場フォーマット変更管理の複雑化 |
| コミュニケーション方法 | 日次 Ops レポート・Azure Monitor アラート |
| 主な要求機能 | バッチ監視ダッシュボード・手動再実行機能・テナント別ログフィルタリング・アラート設定 |

### SH-03: テナント管理者（顧客企業 IT 担当）

| 項目 | 内容 |
|------|------|
| 組織 | テナント（EC 事業者）の IT 部門（テナントあたり 1〜3 名） |
| 主な関心事 | 20 分以内のオンボーディング完了・Entra ID SSO の簡単設定・工場設定の管理画面操作・バッチ実行状況の確認・解約後のデータエクスポート |
| 懸念事項 | 工場フォーマット変更時の対応手順・バッチ失敗時の連絡フロー・データ保持期間 |
| コミュニケーション方法 | Web オンボーディングガイド・管理サイト内ヘルプ・サポートチケット |
| 主な要求機能 | テナント登録フォーム・工場設定管理画面・バッチ状況ダッシュボード・データエクスポート |

### SH-04: 店舗スタッフ（ショップ管理者/スタッフ）

| 項目 | 内容 |
|------|------|
| 組織 | テナント（EC 事業者）の店舗運営チーム（テナントあたり 1〜50 名） |
| 主な関心事 | 管理サイトの直感的な操作・Entra ID SSO によるシームレスなログイン・注文処理の効率化・昨日のバッチ処理結果の確認 |
| 懸念事項 | 現行システムからの移行時の操作変更 |
| コミュニケーション方法 | 管理サイト内のチュートリアル・操作動画 |
| 主な要求機能 | 管理サイト（注文管理・在庫管理）・バッチ状況確認（自テナントのみ） |

### SH-05: 消費者（エンドユーザー）

| 項目 | 内容 |
|------|------|
| 規模 | テナントあたり〜10 万名（ShopHub SaaS 全体で〜100 万名） |
| 主な関心事 | 商品の見つけやすさ・決済の安全性・注文確認メールの受信・個人情報の保護 |
| 懸念事項 | 個人情報漏洩・不正決済・購入完了メールの未着 |
| コミュニケーション方法 | EC サイトの UI・注文確認メール |
| 主な要求機能 | EC サイト（商品検索・カート・Stripe 決済・注文履歴・注文キャンセル） |

### SH-06: 工場システム担当者（外部関係者）

| 項目 | 内容 |
|------|------|
| 組織 | 各テナントが契約する製造工場のシステム担当（テナントあたり 1〜10 工場） |
| 主な関心事 | **毎朝 4:00 JST 前にデータが届いていること（製造スケジュールへの影響防止）**・工場固有フォーマットへの対応・SFTP/Blob 接続の安定性・転送完了通知の受信・データ欠損・重複の防止 |
| 懸念事項 | フォーマット変更時の事前通知不足・転送失敗の検知遅延・テナント A のデータがテナント B の工場に届くこと（データ混入） |
| コミュニケーション方法 | テナント管理者を通じた調整・工場担当者への転送完了通知（Webhook/メール）・障害時のアラートメール |
| 主な要求機能 | 工場ごとの CSV フォーマット定義（BR-FACTORY-01）・SFTP/Blob 転送（BR-FACTORY-02）・転送完了通知（BR-FACTORY-08）・PGP 暗号化（オプション、BR-FACTORY-06） |
| 制約・特記事項 | **工場ごとに独自のフォーマット要件（列名・エンコーディング・区切り文字）を持つ。フォーマット変更には事前通知と十分なリードタイムが必要。** |

### SH-07: 情報セキュリティ部門

| 項目 | 内容 |
|------|------|
| 組織 | SaaS 事業者の情報セキュリティ部門 |
| 主な関心事 | テナント間データ漏洩の技術的証明（Entra ID テナント分離・JWT iss 検証）・バッチ処理のテナント間データ混入防止・SFTP SSH キー管理・PGP 暗号化・監査ログの完全性・ペネトレーションテスト実施 |
| 懸念事項 | テナント間データ漏洩インシデント・バッチ出力ファイルへのデータ混入・SFTP 秘密鍵の漏洩 |
| コミュニケーション方法 | セキュリティレビュー会議・ペネトレーションテストレポート |
| 主な要求機能 | JWT iss クレーム検証（FR-011）・Azure Key Vault 管理・バッチテナント分離（Isolation.Batch）・監査ログ（FR-011） |

### SH-08: 法務部門

| 項目 | 内容 |
|------|------|
| 組織 | SaaS 事業者の法務部門 |
| 主な関心事 | 個人情報保護法（消費者個人情報の管理・削除・エクスポート対応）・特定商取引法（EC サイト表示テンプレート）・PCI DSS 準拠（Stripe 活用）・データ処理契約（DPA）・バッチログ・転送ログの監査証跡 |
| 懸念事項 | 規制違反によるペナルティ・消費者からの個人情報削除請求への対応 |
| コミュニケーション方法 | 法務レビュー会議（リリース前必須） |

## 4. コミュニケーション計画

| ステークホルダー | 頻度 | 手段 | 内容 |
|--------------|------|------|------|
| SH-01（スポンサー） | 月次 | Executive Report・会議 | KPI（ARR・テナント数・バッチ完了率）・マイルストーン状況 |
| SH-02（PF 管理者） | 日次 | Azure Monitor ダッシュボード・Slack | バッチ状況・アラート・テナント数 |
| SH-03（テナント管理者） | 随時 | 管理サイト内通知・メール | プロビジョニング完了・バッチ結果・課金情報 |
| SH-06（工場担当者） | 日次（自動） | Webhook / メール | 転送完了通知（ファイル名・件数・完了時刻） |
| SH-07（情報セキュリティ） | フェーズ区切り | セキュリティレビュー | テナント分離設計レビュー・ペネトレーションテスト結果 |
| SH-08（法務） | リリース前 | 法務レビュー会議 | 特定商取引法対応・個人情報保護法準拠確認 |
