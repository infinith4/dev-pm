## 5. リスクと軽減策

| リスク ID | リスク内容 | 確率 | 影響度 | 軽減策 | 担当 |
|---------|---------|------|-------|-------|------|
| RISK-01 | Azure Batch でのスケーリング設計が 100 万件/テナント・1,000 万件/日の負荷に対応できない | 0.3 | 9 | Phase 2 の DES-04 で早期検証（Spike）を実施。TBD-SRS-02 の解決を Phase 4 テスト前に完了 | 田中 誠 |
| RISK-02 | 工場ごとの CSV フォーマット定義の変更管理が複雑になる | 0.5 | 6 | フォーマット定義をデータベースで管理し、管理画面から変更可能にする（NFR-MAINT-02）。DES-05 でデータモデルを確定 | 田中 誠 |
| RISK-03 | Entra ID テナントの自動プロビジョニングが Microsoft Graph API の制限に引っかかる | 0.4 | 7 | Phase 2 で Microsoft Graph API の Spike 検証を実施（DES-02）。手動フォールバックフローを準備 | チーム A |
| RISK-04 | 工場 SFTP サーバーへの接続テストが遅延し、テストフェーズ（Phase 4）に影響 | 0.4 | 7 | 工場担当者との早期ヒアリング（TBD-SRS-03 を 2026-04-30 までに解決）。テスト環境を先行構築 | 佐藤 花子 |
| RISK-05 | PGP 暗号化の鍵管理が運用負荷になる | 0.3 | 5 | Azure Key Vault で一元管理。鍵更新プロセスをドキュメント化 | 田中 誠 |
