## ユーザーストーリー

**As a** 新規に ShopHub SaaS を契約したテナント管理者（EC 事業者の IT 担当）

**I want to** サインアップフォームを送信するだけで EC サイト・管理サイト・Entra ID テナントが自動的に用意され、利用する工場の設定まで完了したい

**So that** 最短当日中に EC サイトと管理サイトを使い始められ、翌夜から夜間バッチで工場に注文データが自動送信される状態にしたい

## 受入基準

### AC-001: テナント登録フォームの送信

**Given** ShopHub SaaS のサインアップページ

**When** テナント管理者が企業名・スラッグ（`myshop`）・代表メールアドレス・Professional プランを選択してフォームを送信し、メール確認リンクをクリックする

**Then**
- スラッグ `myshop` がプラットフォーム内で一意であることが確認される（BR-MT-10）
- メール確認完了から 20 分以内にプロビジョニングが完了する（BR-MT-01）
- Stripe でトライアルサブスクリプション（14 日間、Professional 相当）が作成される（BR-MT-30）

### AC-002: Entra ID テナントの自動作成

**Given** テナント登録が完了している

**When** プロビジョニング処理が実行される

**Then**
- Microsoft Graph API でテナント A 専用の Entra ID テナントが自動作成される（BR-MT-02）
- 管理サイト用 OIDC アプリ（`ShopHub.Admin`・`ShopHub.Staff` ロール定義含む）が Entra ID テナントに登録される
- EC サイト用 Azure AD External Identities（CIAM）が設定される（BR-MT-03）
- 手動操作なしで完了する（BO-3）

### AC-003: PostgreSQL DB・Blob コンテナの作成

**Given** Entra ID テナントの作成が完了している

**When** プロビジョニングが継続される

**Then**
- テナント A 専用の PostgreSQL Flexible Server インスタンスが作成される
- テナント A 専用の Blob Storage コンテナ（`tenant-{tenant_id}`）が作成される
- Azure Key Vault に DB 接続文字列・API キーが登録される
- Azure Front Door にカスタムドメイン（`shop.myshop.jp` / `admin.myshop.jp`）が設定される

### AC-004: プロビジョニング失敗時のロールバック

**Given** プロビジョニング中に PostgreSQL DB 作成が失敗した

**When** エラーが検知される

**Then**
- 作成済みリソース（Entra ID テナント・Blob コンテナ等）がすべて削除される（BR-MT-04）
- テナント状態が `provisioning_failed` に設定される
- プラットフォーム管理者にアラートメールが送信される
- テナント管理者にエラー通知と再試行の案内が表示される

### AC-005: プロビジョニング完了後のログイン確認

**Given** プロビジョニングが完了している

**When** テナント管理者が `admin.myshop.jp` にアクセスする

**Then**
- テナント A 専用の Entra ID テナントの OIDC 認証にリダイレクトされる
- ログイン成功後、管理サイトのダッシュボードが表示される（UC-002）
- JWT の `iss` クレームにテナント A の Entra ID テナント ID が含まれる（BR-MT-22）
- テナント B の管理サイトへのアクセスは拒否される（FR-011）

### AC-006: スラッグの一意性と変更禁止

**Given** スラッグ `myshop` が既に別テナントに使用されている

**When** 新規テナント管理者が `myshop` で登録しようとする

**Then**
- スラッグの重複エラーが表示される（BR-MT-10）
- 別のスラッグを入力するよう促される

**Given** テナント登録が完了している

**When** テナント管理者がスラッグを変更しようとする

**Then**
- スラッグの変更は不可能である（BR-MT-11）
- 変更不可の旨が表示される

### AC-007: プラン変更（Starter → Professional）

**Given** Starter プランでテナントが存在する

**When** テナント管理者が Professional プランにアップグレードする

**Then**
- アップグレードが即日適用される（BR-MT-34）
- 差額が日割り計算で Stripe から課金される
- 夜間バッチ処理（FR-020）と工場データ連携（FR-021）が利用可能になる（BR-BATCH-06）

### AC-008: 解約後のデータ保持

**Given** テナントが解約処理を行った

**When** 解約が完了する

**Then**
- 解約後 90 日間、注文・商品・バッチログ・転送ログがテナント DB に保持される（BR-MT-40）
- テナント管理者は保持期間中にデータを CSV/JSON でエクスポートできる
- 90 日経過後に DB・Blob・Entra ID テナントが物理削除される（BR-MT-41）

### AC-009: 工場設定の登録

**Given** テナント登録が完了し Professional プランで `active` 状態

**When** テナント管理者が管理サイトから工場（工場コード: `FACTORY-A`、転送方式: SFTP、フォーマット定義: 工場A標準フォーマット v2）を登録する

**Then**
- 工場マスタに工場情報が保存される（BR-FACTORY-01）
- SFTP 接続テストが成功する
- 工場設定が管理画面に表示される
- Starter プランでは工場登録が拒否される（BR-MT-31）

### AC-010: 工場設定後の夜間バッチ対象追加

**Given** テナントに工場 `FACTORY-A` が設定されている

**When** 当日 22:00 に夜間バッチが起動する

**Then**
- テナントのバッチジョブがスケジューリングされる
- `FACTORY-A` 向けに注文データが CSV フォーマットに変換される
- SFTP サーバーにファイルが転送される（BR-FACTORY-02）
- 転送完了通知（メール）が工場担当者に送信される（BR-FACTORY-08）

---

## 技術メモ

- **Microsoft Graph API**: テナントプロビジョニングに使用（Entra ID テナント作成・CIAM 設定・OIDC アプリ登録）
- **Azure Batch**: 工場設定完了後から夜間バッチの対象テナントとして自動的に追加
- **工場マスタ**: Platform DB の `factory_masters` テーブルで管理（テナント専用 DB ではなく共有の Platform DB）
