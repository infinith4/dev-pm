## 1. 目的

- 機能要件を一覧で把握し、スコープと優先度を可視化する
- 個別機能要件定義書（`FR-XXX-*.md`）への導線を提供する
- ユースケース、ユーザーストーリー、設計、テストとのトレーサビリティ起点にする

---

## 2. 記載ルール

### 2.1 ID 規約

- 機能IDは `FR-{連番3桁}` 形式とする
- 個別ファイル名は `FR-{連番3桁}-{機能名（ケバブケース）}.md` とする
- 一度採番した ID は削除後も再利用しない

### 2.2 優先度定義

- **Must**: リリースに必須
- **Should**: 重要だが必須ではない
- **Could**: あれば望ましい
- **Won't**: 今回のスコープ外

### 2.3 運用ルール

- 一覧に追加した機能は、対応する個別 FR ファイルを必ず作成する
- 優先度、ステータス、対象リリースが変わった場合は一覧と個別 FR の双方を更新する
- 関連する UC / US / BO / BR が未確定の場合は `TBD` と記載し、個別 FR 側に詳細を残す

## 5. レビュー観点

- すべての機能に一意の `FR-ID` が割り当てられているか
- `機能概要` がユーザー価値または業務価値を説明しているか
- `優先度` と `対象リリース` が整合しているか
- すべての機能に個別 FR ファイル、関連 UC / US がひも付いているか
- Out of Scope の機能が `Won't` または別文書で明示されているか
