## 目的

ビジネスルールはプロジェクト固有の成果物ではなく、エンタープライズレベルの資産である。企業ポリシー、政府規制、業界標準、計算アルゴリズムなどを、個別のソフトウェア要件とは独立して管理する。

ビジネスルールから機能要件が派生する。ルールが変更された場合、関連する機能要件を特定し更新できるよう、トレーサビリティを維持する。

---

## ルール種別

| 種別 | 説明 | 例 |
| --- | --- | --- |
| **Fact** | 常に真であるアサーション | 「注文は1つ以上の商品を含む」 |
| **Constraint** | 許容されるアクションや状態への制約 | 「未成年者はアルコール商品を購入できない」 |
| **Action Enabler** | 条件が満たされたときにアクションを起動する | 「化学薬品の有効期限が到来したら所有者に通知する」 |
| **Inference** | 既存の事実から新しい事実を導出する | 「3回連続で遅延した場合、そのサプライヤーはリスク扱いとする」 |
| **Computation** | 計算式またはアルゴリズム | 「送料 = 基本料金 + (重量 x 単価) + 地域加算」 |

## ルール管理方針

- 新規ルール追加時は、必ずソース（法規制、ポリシー文書等）を記録する
- ルール変更時は、「派生要件」列を確認し、影響を受ける機能要件を更新する
- 廃止されたルールはステータスを `Deprecated` に変更し、削除はしない
- ルールIDは一度付与したら再利用しない
