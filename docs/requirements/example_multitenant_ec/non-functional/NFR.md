## 品質属性の優先順位

ShopHub SaaS における品質属性の優先順位（高い順）:

1. **セキュリティ** - Entra ID テナント分離・CIAM・JWT iss 検証・バッチデータ混入防止・暗号化
2. **可用性** - SLA 99.9%・バッチ処理の継続性・工場データ納期保証
3. **スループット（バッチ）** - 1,000 万件/日（全テナント合計）をキュー駆動で継続処理
4. **スケーラビリティ** - テナント数の増加・バッチノード数の動的スケールへの対応
5. **パフォーマンス** - EC サイトのユーザー体験（P95 ≤ 200ms、10,000 req/sec 対応）
6. **保守性** - バッチの手動再実行・フォーマット定義の管理画面・テナント別ログ

## 1. セキュリティ（Security）

### 1.1 テナント分離・認証

| NFR-ID | 要件 | 目標値 | 測定方法 |
|--------|------|-------|---------|
| NFR-SEC-01 | テナント間データ漏洩インシデント | 0 件 | セキュリティ監査ログ・ペネトレーションテスト |
| NFR-SEC-02 | JWT iss クレーム検証 | 全 API リクエストで 100% 検証 | ユニットテスト・結合テスト |
| NFR-SEC-03 | テナント別 DB 分離 | Bridge モデル（テナントごとに独立した PostgreSQL インスタンス） | インフラ構成レビュー |
| NFR-SEC-04 | バッチ処理のテナント間データ混入 | 0 件 | バッチ出力の自動検証テスト |
| NFR-SEC-05 | SFTP 接続 | SSH キー認証のみ（パスワード認証禁止） | セキュリティ設定レビュー |

### 1.2 暗号化

| NFR-ID | 要件 | 目標値 | 測定方法 |
|--------|------|-------|---------|
| NFR-SEC-10 | 通信の暗号化 | TLS 1.3 以上（全通信） | SSL Labs テスト |
| NFR-SEC-11 | シークレット管理 | Azure Key Vault に集約（コード・ログへの漏洩禁止） | コードレビュー・SAST |
| NFR-SEC-12 | PGP 暗号化（工場） | 工場マスタで設定された場合に適用 | 転送ログの確認 |
| NFR-SEC-13 | カード情報の非保持 | Stripe 管理（システム内に保存禁止） | PCI DSS 準拠審査 |
| NFR-SEC-14 | データ居住地 | 日本国内 Azure リージョン（Japan East / Japan West）のみ | Azure ポリシー・インフラレビュー |

### 1.3 MFA・条件付きアクセス

| NFR-ID | 要件 | 目標値 | 測定方法 |
|--------|------|-------|---------|
| NFR-SEC-20 | 管理サイトの MFA | Entra ID 条件付きアクセスポリシーで MFA を必須化 | Entra ID 設定レビュー |
| NFR-SEC-21 | プラットフォーム管理者の MFA | 必須（例外なし） | Azure ポリシー |

## 3. バッチ処理性能（Batch Performance）

### 3.1 処理完了時間

| NFR-ID | 要件 | 目標値 | 根拠 | 測定方法 |
|--------|------|-------|------|---------|
| NFR-BATCH-01 | 注文確定からバッチ転送完了までの最大遅延 | 90 分以内（TimeFlush 30 分 + 処理 + 転送） | SM-5, BR-BATCH-03 | E2E レイテンシ計測 |
| NFR-BATCH-02 | テナントあたりの最大注文件数 | 100 万件/日 | AS-3 | 負荷テスト（Phase 4） |
| NFR-BATCH-03 | バッチ処理の並列度 | Azure Batch ノード数でキュー深度に応じた動的スケール | NFR-SCAL-03 参照 | Azure Batch メトリクス |
| NFR-BATCH-04 | バッチ失敗率（月次） | < 0.1% | BO-4 | Azure Monitor バッチ失敗ログ |
| NFR-BATCH-05 | バッチ処理スループット | テナントあたり 100 万件を 3 時間以内 | NFR-BATCH-02 より逆算 | 負荷テスト |

| NFR-ID | 要件 | 目標値 | 根拠 | 測定方法 |
|--------|------|-------|------|---------|

## 6. スケーラビリティ（Scalability）

| NFR-ID | 要件 | 目標値 | 測定方法 |
|--------|------|-------|---------|
| NFR-SCAL-01 | テナント数 | 200 テナント以上に対応（Release 1: 100 テナント目標） | インフラキャパシティテスト |
| NFR-SCAL-02 | アプリケーション Auto Scaling | CPU 使用率 70% 閾値でスケールアウト | Azure Container Apps メトリクス |
| NFR-SCAL-03 | Azure Batch ノード数の動的スケール | キュー長に応じて 0〜100 ノードの間でスケール | Azure Batch 設定・テスト |
| NFR-SCAL-04 | Azure Cognitive Search インデックス数 | テナント数分のインデックスを管理（最大 200 インデックス） | Azure Cognitive Search 設定確認 |
| NFR-SCAL-05 | Noisy Neighbor の防止 | 特定テナントのバッチジョブが他テナントのジョブに影響しない | 負荷テスト（テナント間干渉テスト） |

| NFR-MAINT-01 | バッチの手動再実行 | テナント ID・対象日を指定して管理画面から再実行可能 | 機能テスト |
