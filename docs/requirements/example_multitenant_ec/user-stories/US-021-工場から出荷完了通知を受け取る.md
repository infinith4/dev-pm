## ユーザーストーリー

**As a** ShopHub SaaS を利用するテナント管理者（EC 事業者）

**I want to** 工場が注文データを受け取って出荷完了したら、ShopHub に自動的に通知が届いてほしい

**So that** 消費者に迅速に発送通知メールが届き、管理サイトで出荷状況を把握できるようにしたい

---

## 受入基準

### AC-001: 工場から出荷完了通知を受信すると注文ステータスが更新される

**Given** 工場 A（FACTORY-A）が夜間バッチで受け取った CSV の 50 件の注文を出荷完了し、ShopHub の通知エンドポイントに HTTPS POST を送信する

**When** 通知を受信する

**Then**
- 50 件の注文ステータスが `confirmed` から `shipped` に更新される（BR-FACTORY-15）
- `orders.shipped_at` に工場からの `shipped_at` 日時が記録される
- 追跡番号が含まれる場合は `order_shipping_info` テーブルに記録される
- HTTP 200 レスポンスが工場システムに返される

### AC-002: 消費者に発送通知メールが送信される

**Given** 50 件の注文のうち 48 件に消費者メールアドレスが存在する（2 件はゲスト購入で未登録）

**When** 注文ステータスが `shipped` に更新される

**Then**
- 48 件の消費者に発送通知メール（テナントブランド名・注文番号・出荷日時・追跡番号・配送先）が送信される（BR-FACTORY-15）
- メールは通知受信から 1 分以内に送信される
- ゲスト購入 2 件はメール送信をスキップし、ログに記録される
- メールテンプレートはテナントのカスタムテンプレートが適用される

### AC-003: 管理サイトで出荷状況がリアルタイムに確認できる

**Given** 店舗スタッフが管理サイトの注文一覧画面を開いている

**When** 工場からの出荷完了通知が受信される

**Then**
- 注文一覧の対象注文のステータスが `shipped` にリアルタイムで更新される
- 通知バナー「工場 A から 50 件の出荷完了通知を受信しました」が表示される
- 注文詳細画面で追跡番号・配送業者・出荷日時が確認できる

### AC-004: HMAC 署名検証で不正なリクエストを拒否する

**Given** 第三者が工場になりすまし、不正な HMAC 署名でエンドポイントにアクセスする

**When** HMAC-SHA256 署名の検証が失敗する

**Then**
- HTTP 401 が返される（BR-FACTORY-12）
- 注文ステータスは更新されない
- Azure Monitor にセキュリティアラートが記録される
- 同一 IP から 10 回連続失敗した場合、プラットフォーム管理者に通知が届く

### AC-005: 同一注文への重複通知を安全にスキップする

**Given** 工場システムのリトライにより、同一注文（order_id: `myshop-20261201-00000001`）への通知が 2 回送信される

**When** 2 回目の通知を受信する

**Then**
- 2 回目の通知はスキップされ、注文ステータスは二重更新されない（BR-FACTORY-14）
- HTTP 200 レスポンスが返される（`skipped_order_ids` に `myshop-20261201-00000001` が含まれる）
- 消費者への発送通知メールは重複して送信されない

### AC-006: テナント A の工場がテナント B の注文を更新できない

**Given** テナント A の工場システムが、誤ってテナント B の注文 ID を含む通知を送信する

**When** テナント・工場の対応確認（BR-FACTORY-13）を実施する

**Then**
- HTTP 403 が返される
- テナント B の注文ステータスは更新されない
- クロステナント誤送信として Azure Monitor にセキュリティアラートが記録される
- テナント A の管理者に設定確認の通知が届く

### AC-007: 管理サイトで出荷完了通知の受信ログを確認できる

**Given** テナント管理者が管理サイトの工場連携ログ画面にアクセスする

**When** 直近 30 日間のログを確認する

**Then**
- 工場別・日別の受信ログ（受信日時・件数・成功/スキップ/エラー件数）が表示される
- 各ログのエラー詳細（失敗した `order_id` 一覧）が確認できる
- エラーが発生した通知については管理サイトから手動で消費者メールを再送できる

### AC-008: 工場マスタで通知受信 URL と HMAC キーを管理できる

**Given** テナント管理者が工場マスタの設定画面を開く

**When** 工場の出荷完了通知設定を確認する

**Then**
- 通知受信 URL（`https://api.shophub.example/api/v1/factories/{factory_id}/ship-notify`）が表示される
- HMAC キー（マスク表示）を確認・再発行できる
- `ship_notify_enabled` を ON/OFF に切り替えられる

## 技術メモ

- **Webhook 受信**: Azure API Management（APIM）経由で受け付け、HMAC-SHA256 署名を検証する
- **冪等性**: 同一 `order_id` への重複更新を防ぐため、`shipped` 状態チェックを DB トランザクション内で実施する
- **メール送信**: Azure Communication Services または SendGrid を使用。失敗時はキューに保持して最大 3 回リトライする
- **リアルタイム反映**: 管理サイトへの反映は WebSocket または Server-Sent Events（SSE）を使用する
- **HMAC キー管理**: 工場ごとの HMAC-SHA256 キーは Azure Key Vault に保存し、管理サイトからの再発行に対応する
- **テナントデータ分離**: 工場の `factory_id` から `tenant_id` を導出し、ペイロードの `tenant_id` と一致することをすべてのリクエストで検証する（FR-011）
