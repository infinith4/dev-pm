## 1. Business Requirements

### 1.1 Background

株式会社〇〇では現在、プロジェクトのタスク管理を Excel シートとメールで行っている。担当者は1日平均 45 分をタスク状況の確認・更新・報告メールの作成に費やしており、進捗の把握に遅延が生じることが常態化している。また、複数プロジェクトに参加するメンバーは各プロジェクトの Excel を個別に管理する必要があり、参照漏れや更新漏れが月平均 12 件発生している。リモートワーク推進により、リアルタイムな状況共有の必要性がさらに高まっている。

### 1.2 Business Opportunity

チームメンバーがブラウザからリアルタイムにタスクを登録・更新・確認できる Web アプリを提供することで、進捗管理の工数を大幅に削減できる。また、ステータス変更・コメント追加を通知することでチーム間の情報伝達をシステム化し、報告メールの作成コストを排除できる。初年度は社内向けで展開し、将来的には外部向け SaaS 化も視野に入れる。

### 1.3 Business Objectives

| Meter（測定方法） | 四半期ごとのアンケート調査（n ≥ 50） |
| Past（現状値） | 45 分（2025年Q3調査） |

| Stretch（努力目標） | 10 分以下 |
| 期限 | リリース後 6 ヶ月（2026-09-30） |

| Meter | インシデント管理システムのログ集計 |

| Goal | 月 2 件以下 |

### 1.5 Vision Statement

> **For** プロジェクトチームのメンバーおよびマネージャー
> **Who** タスクの進捗把握・更新に手間がかかり、情報共有の遅延に悩んでいる
> **The** TaskBoard
> **Is a** ブラウザベースのプロジェクトタスク管理 Web アプリケーション
> **That** タスクの登録・ステータス更新・担当者割り当て・コメント・通知をリアルタイムで提供し、チームの進捗を一元管理する
> **Unlike** Excel シートとメールによる現行プロセス
> **Our product** ブラウザからリアルタイムに全員が同じ情報を参照・更新でき、変更通知が自動送信されるため、報告メールや集計作業が不要になる

### 1.6 Business Risks

| リスクID | リスク | 確率 | 影響度 | 軽減策 |
|---------|-------|------|-------|-------|
| RI-1 | Excel 運用に慣れたユーザーが移行を拒否し、利用率が低迷する | 0.4 | 9 | 早期に現場担当者をパイロットユーザーとして参画させ、フィードバックを反映する |
| RI-2 | リリース後に想定外の機能要求が発生し、スコープが膨張する | 0.6 | 6 | ベースライン確定後の変更管理プロセス（CR フロー）を厳格に運用する |
| RI-3 | 外部 ID プロバイダー（Azure AD）との連携開発が遅延する | 0.3 | 6 | Spike を早期に実施し、連携方式の技術検証を Release 1 開始前に完了させる |
| RI-4 | セキュリティ審査で要件追加が発生し、スケジュールに影響する | 0.3 | 6 | 情報セキュリティ部門を設計フェーズから参画させる |

### 1.7 Business Assumptions and Dependencies

#### Assumptions

| ID | 前提条件 | 誤りだった場合の影響 |
|----|---------|----------------|
| AS-1 | 全社員が Azure AD アカウントを保有している | シングルサインオン実装の見直しが必要になり、認証機能の工数が増加する |
| AS-2 | 社内ネットワークから HTTPS でアクセスできる環境が整っている | インフラ整備が前提となり、リリース日程に影響する |
| AS-3 | 全社員が Chrome / Edge 最新版を利用していること | IE 等レガシーブラウザ対応が必要になる |

#### Dependencies

| ID | 依存先 | 説明 | 影響範囲 |
|----|-------|------|---------|
| DE-1 | Azure Active Directory | SSO のため Azure AD と連携する必要がある | ユーザー認証全般 |
| DE-2 | 通知メールサーバー（SendGrid） | タスク更新通知をメール送信するために利用する | 通知機能 |

## 2. Scope and Limitations

### 2.1 Major Features

| 機能ID | 機能名 | 説明 | 優先度 |
|-------|-------|------|-------|
| FE-1 | タスク管理 | タスクの作成・閲覧・更新・削除、ステータス管理（未着手/進行中/完了/保留） | Must |
| FE-2 | プロジェクト管理 | プロジェクトの作成・メンバー招待・アーカイブ | Must |
| FE-3 | ユーザー認証・認可 | Azure AD SSO / メール+パスワード認証、RBAC（PM/開発者/閲覧者） | Must |
| FE-4 | コメント・活動ログ | タスクへのコメント投稿、変更履歴の記録 | Should |
| FE-5 | 通知機能 | タスク割り当て・ステータス変更時のメール/アプリ内通知 | Should |
| FE-6 | ダッシュボード・レポート | プロジェクト進捗サマリー、バーンダウンチャート、メンバー稼働状況 | Could |
| FE-7 | 外部ツール連携 | GitHub Issues / Jira との双方向同期 | Won't（Release 1） |

### 2.2 Scope of Initial and Subsequent Releases

| 機能 | Release 1 | Release 2 | Release 3 |
|-----|----------|----------|----------|
| FE-1 タスク管理 | 基本 CRUD・ステータス管理 | ラベル/マイルストーン対応 | 繰り返しタスク・サブタスク |
| FE-2 プロジェクト管理 | 作成・メンバー招待のみ | アーカイブ・テンプレート | マルチワークスペース |
| FE-3 認証・認可 | メール+パスワード認証・RBAC | Azure AD SSO 追加 | 多要素認証 |
| FE-4 コメント | 未実装 | コメント投稿・活動ログ | リアクション・メンション |
| FE-5 通知 | メール通知のみ | アプリ内通知 | Slack / Teams 連携 |
| FE-6 ダッシュボード | 未実装 | 進捗サマリー | バーンダウンチャート |
| FE-7 外部連携 | 未実装 | 未実装 | GitHub Issues 連携 |

### 2.3 Limitations and Exclusions

| ID | 対象外事項 | 対象外の理由 |
|----|---------|-----------|
| LI-1 | 工数管理・勤怠連携 | スコープが大幅に拡大するため次フェーズで検討する |
| LI-2 | 予算・コスト管理機能 | 既存の会計システムで管理されており重複を避ける |
| LI-3 | スマートフォンアプリ（iOS/Android ネイティブ） | Release 1 はブラウザのレスポンシブ対応のみ |

## 3. Business Context

### 3.1 Stakeholder Profiles

| ステークホルダー | 主な価値 | 姿勢・懸念 | 主な関心事 | 制約 |
|--------------|---------|---------|---------|------|
| 事業部長（スポンサー） | Excel 廃止によるコスト削減と生産性向上 | 強くコミット。ROI を重視 | 投資対効果・リリース日程 | 特になし |
| プロジェクトマネージャー | 進捗の一元管理・レポート自動化 | 強く期待。早期導入を希望 | 使いやすさ・レポート機能 | 既存 Excel の移行工数への懸念 |
| 開発者・メンバー | タスク状況の素早い確認と更新 | 概ね賛成。UI の使いやすさを重視 | 更新の手軽さ・通知の適切さ | 現業との兼務による利用時間の制約 |
| 情報システム部門 | セキュリティ・運用管理性 | Azure AD 連携に積極的 | セキュリティ・可用性・保守性 | 社内セキュリティ審査通過が必要 |

### 3.3 Deployment Considerations

- **移行戦略**: 段階的移行。パイロット部門（開発部 20名）→全社展開の順で実施する。
- **データ移行**: 既存 Excel タスクのインポート機能（CSV 取込）を Release 1 に含める。
- **トレーニング**: オンラインマニュアルと 30 分のハンズオン動画を用意する。現地トレーニングは PM 向けのみ実施。
- **ロールアウト**: 開発部（Week 1）→ 営業部（Week 3）→ 管理部門（Week 5）の順で展開する。
