### 概要

プロジェクトメンバーがタスクを作成・閲覧・更新・削除し、ステータスと担当者を管理する中核機能。タスクは常に1つのプロジェクトに属し、作成後は「未着手」から開始して「完了」まで遷移する。

---

### 機能要件

---

**Task.Create: タスクの作成**

**.Title**: システムは、ユーザーがタスクのタイトル（必須、最大 200 文字）を入力できるようにしなければならない。（BR-10）

**.Description**: システムは、ユーザーがタスクの説明（任意、最大 2,000 文字、Markdown 記法対応）を入力できるようにしなければならない。

**.Assignee**: システムは、ユーザーがタスクの担当者をプロジェクトメンバーの中から選択できるようにしなければならない。担当者は任意項目とし、未選択時は「未割り当て」で作成する。（BR-2）

**.DueDate**: システムは、ユーザーがタスクの期限（任意）を設定できるようにしなければならない。

**.Priority**: システムは、ユーザーがタスクの優先度（高 / 中 / 低、デフォルト：中）を選択できるようにしなければならない。

**.Status**: システムは、作成されたタスクのステータスを自動的に「未着手」に設定しなければならない。（BR-1）

**.ID**: システムは、作成されたタスクに対してプロジェクト内で一意のタスク ID を採番しなければならない。

**.Notify**: 担当者が指定された場合、システムは担当者に割り当て通知メールを送信しなければならない。通知の失敗はタスク保存処理をロールバックしてはならない。（→ UC-001 ステップ 6 参照）

**.Log**: システムは、タスク作成イベントを活動ログに記録しなければならない（作成者・作成日時・タスク ID）。

---

**Task.Read: タスクの閲覧**

**.List**: システムは、プロジェクトに属するタスクの一覧をプロジェクトメンバー全員が閲覧できるようにしなければならない。

**.Filter**: システムは、ステータス・担当者・優先度・期限によるフィルタリングをサポートしなければならない。

**.Sort**: システムは、作成日・更新日・期限・優先度による並び替えをサポートしなければならない。

**.Detail**: システムは、タスクの詳細画面でタイトル・説明・ステータス・担当者・期限・優先度・作成者・作成日時・更新日時・活動ログを表示しなければならない。

**.Search**: システムは、タイトルおよび説明のキーワード全文検索をサポートしなければならない。 [TBD-001-01: 検索エンジンの実装方式（PostgreSQL FTS / ElasticSearch）、担当: Architect、期限: 2026-02-28]

---

**Task.Update: タスクの更新**

**.Status**: プロジェクトマネージャーおよび開発者は、タスクのステータスを更新できなければならない。ステータス遷移は BR-1 の定義に従う。

**.StatusTransition**: システムは BR-1 に定義された不正なステータス遷移を拒否し、エラーメッセージを表示しなければならない。

**.Fields**: 担当者・期限・優先度・タイトル・説明は更新できなければならない。

**.Assignee**: 担当者が変更された場合、システムは新しい担当者に割り当て変更通知メールを送信しなければならない。

**.Log**: システムは、すべてのフィールド変更を活動ログに記録しなければならない（変更者・変更日時・変更前後の値）。

---

**Task.Delete: タスクの削除**

**.Auth**: タスクを削除できるのはプロジェクトマネージャーのみとする。（BR-2）

**.Confirm**: システムは、タスク削除前に確認ダイアログを表示しなければならない。

**.Soft**: システムは、削除されたタスクを物理削除せず、ステータスを「削除済み」に設定して論理削除しなければならない。削除済みタスクは通常の一覧には表示しない。

**.Restore**: プロジェクトマネージャーは削除後 30 日以内であれば削除済みタスクを復元できなければならない。（BR-6）

---

**Task.Done: タスク完了時のアトミック処理**

システムは、タスクが「完了」に更新された際、以下の処理を単一トランザクションで実行しなければならない。

**.Timestamp**: 完了日時をタスクレコードに記録する。

**.Log**: 活動ログに完了イベントを追記する。

**.Notify**: プロジェクトマネージャーに完了通知メールを送信する（非同期処理、失敗時は再送キューに登録）。

**.Failure**: いずれかのステップが失敗した場合、システムはトランザクションをロールバックし、ユーザーに「タスクの更新に失敗しました」と通知しなければならない。

---

### 入力・出力

#### 入力（タスク作成・更新時）

| フィールド | 型 | 必須 | 制約 | 説明 |
|----------|----|----|------|------|
| title | string | 必須 | max 200文字 | タスクタイトル |
| description | string | — | max 2,000文字、Markdown | タスク説明 |
| assignee_id | integer | — | プロジェクトメンバーのユーザーID | 担当者 |
| due_date | date | — | 本日以降（警告のみ、ブロックしない） | 期限 |
| priority | enum | — | HIGH / MEDIUM / LOW（デフォルト: MEDIUM） | 優先度 |
| status | enum | — | 更新時のみ指定可。BR-1 のステータス遷移ルール適用 | ステータス |

#### 出力（タスク詳細）

| フィールド | 型 | 説明 |
|----------|----|----|
| id | integer | タスク ID（プロジェクト内連番） |
| title | string | タスクタイトル |
| description | string | タスク説明 |
| status | enum | 未着手 / 進行中 / 完了 / 保留 / 削除済み |
| assignee | object | { id, name, email } |
| due_date | date | 期限 |
| priority | enum | HIGH / MEDIUM / LOW |
| created_by | object | { id, name } |
| created_at | datetime | 作成日時（UTC） |
| updated_at | datetime | 最終更新日時（UTC） |
| activity_log | array | 活動ログ一覧 |

### 業務ルール参照

| BR-ID | 適用箇所 | ルール概要 |
|-------|---------|---------|
| BR-1 | Task.Update.Status | ステータスは「未着手→進行中→完了」「進行中→保留」「保留→進行中」のみ遷移可。「完了→未着手」は PM のみ可。 |
| BR-2 | Task.Create.Assignee、Task.Delete.Auth | 担当者の割り当てと削除権限はプロジェクトマネージャーと担当者本人のみ。削除は PM のみ。 |
| BR-5 | Task.Create | 1プロジェクト内のアクティブタスク上限は 1,000 件。超過時は警告を表示し作成を拒否する。 |
| BR-6 | Task.Delete.Restore | 論理削除後 30 日を経過したタスクは自動的に物理削除される。 |
| BR-10 | Task.Create.Title | タイトル最大 200 文字、説明最大 2,000 文字。 |

---

### 例外・エラー処理

| ケース | 条件 | システムの応答 |
|-------|------|-------------|
| タイトル未入力 | タイトルが空のまま「作成」を押した | 「タイトルは必須です」とインラインエラーを表示し、フォームを保持する |
| 不正なステータス遷移 | BR-1 に違反するステータス変更を試みた | 「このステータスへの変更はできません」と表示し、変更を拒否する |
| タスク上限超過 | プロジェクトのアクティブタスクが 1,000 件に達した状態で作成しようとした | 「このプロジェクトのタスク上限（1,000件）に達しました。完了済みタスクをアーカイブしてください」と表示する（BR-5） |
| 権限不足 | 閲覧者がタスク作成・更新・削除を試みた | 403 Forbidden。「この操作を行う権限がありません」と表示する |
