# 業務ルールカタログ
## TaskBoard SaaS ─ Azure マルチテナント

> **参考**: Karl Wiegers "Software Requirements 3rd Edition" Chapter 9 "Playing by the Rules"
>
> **業務ルールの分類（Wiegers Chapter 9 より）**:
> - **Fact（事実）**: 常に真であるビジネスの定義や関係性
> - **Constraint（制約）**: 実行できる操作を制限するルール
> - **Action Enabler（アクション起動ルール）**: 特定の条件を満たしたときに実行されるアクション
> - **Inference（推論）**: 既知の情報から新たな情報を導出するルール
> - **Computation（計算）**: 計算式・アルゴリズム

## 1. テナントプロビジョニング

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-01 | Fact | テナントは物理的に独立した PostgreSQL データベース（または DB インスタンス）を持つ（Bridge モデル）。1テナント = 1 DB。 | FR-011, NFR-SEC-01 |
| BR-MT-02 | Constraint | テナント DB の接続文字列・API キーはアプリケーションコード・環境変数・ログに含めてはならない。Azure Key Vault への参照 URI のみを Platform DB に保存する。 | FR-010, NFR-SEC-02 |
| BR-MT-03 | Action Enabler | テナントのメール確認が完了した時点で、プロビジョニングジョブを自動起動しなければならない。プロビジョニングは 3 分以内に完了しなければならない。超過した場合はプラットフォーム管理者にアラートを発報する。 | FR-010, NFR-PRF-03 |
| BR-MT-04 | Constraint | テナント DB は Azure Private Endpoint 経由でのみアクセスを許可する。パブリック IP からの接続を拒否する。 | FR-011, NFR-SEC-01 |
| BR-MT-05 | Constraint | Azure Blob Storage へのアクセスは SAS トークン（有効期限 ≤ 1 時間）を使用する。コンテナレベルまたはアカウントレベルの SAS は発行してはならない。 | FR-011 |

## 2. テナント設定・サブドメイン

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-10 | Constraint | サブドメインは作成後に変更できない。登録後の変更要求は新テナント作成・データ移行で対応する。 | FR-010 |
| BR-MT-11 | Constraint | サブドメインに使用できない予約済みキーワード: `www`, `api`, `admin`, `mail`, `support`, `help`, `app`, `dashboard`, `status`, `billing`, `login`, `signup`（リストは別途管理）。 | FR-010 |
| BR-MT-12 | Inference | テナントのアクティブユーザー上限はプランに基づいて決定される: Starter: 10名 / Professional: 100名 / Enterprise: 1,000名。プランをダウングレードする場合、現在のアクティブユーザー数が新プランの上限を超えていれば、ダウングレードを拒否する。 | FR-010 |
| BR-MT-13 | Computation | テナントのストレージ使用量 = Blob コンテナ内の全ファイルサイズの合計。プランの上限を超えた場合は警告を表示し、新規ファイルのアップロードを拒否する。 | FR-010 |

## 3. 認証・セキュリティ

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-20 | Fact | JWT（アクセストークン）の有効期限は 1 時間。リフレッシュトークンの有効期限は 30 日（「ログインしたままにする」選択時）/ 24 時間（非選択時）。 | FR-010, NFR-SEC-11 |
| BR-MT-21 | Action Enabler | 同一アカウントへのログイン失敗が 5 回連続した場合、アカウントを 30 分間ロックする。ロック発生時にアカウント登録メールアドレスにロック通知を送信する。 | FR-010, NFR-SEC-13 |
| BR-MT-22 | Constraint | パスワードは最低 12 文字、英大文字・英小文字・数字・記号（`!@#$%^&*` 等）を各 1 文字以上含まなければならない。直近 5 回使用したパスワードは再利用できない。 | FR-010 |
| BR-MT-23 | Constraint | テナント A の認証済みユーザーは、いかなる手段によってもテナント B のリソースにアクセスできてはならない（API / DB / ストレージ / 管理画面すべてにおいて）。 | FR-011, NFR-SEC-01 |
| BR-MT-24 | Constraint | Azure Key Vault のシークレットは 90 日ごとに自動ローテーションを実施しなければならない。ローテーション失敗はプラットフォーム管理者に即時アラートを送信する。 | FR-010, NFR-SEC-22 |

## 4. ユーザー管理・招待

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-25 | Constraint | テナントへの招待リンクの有効期限は 7 日間。期限切れの招待リンクは無効となり、テナント管理者が再招待しなければならない。 | FR-010 |
| BR-MT-26 | Constraint | テナント管理者は自身のロールを変更・削除できない（テナントに管理者が 0 名になることを防ぐため）。別の管理者が操作しなければならない。 | FR-010 |
| BR-MT-27 | Fact | ロールの権限定義: テナント管理者（全権）> PM（プロジェクト管理・メンバー管理）> 開発者（タスク CRUD・コメント）> 閲覧者（参照のみ）。 | FR-010 |

## 5. サブスクリプション・課金

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-30 | Fact | 新規テナントはサインアップ後 14 日間の無料トライアルが付与される。トライアル期間中はクレジットカード登録不要で全機能を利用できる。 | FR-010 |
| BR-MT-31 | Fact | プランの定義（月額）: Starter ¥5,000（ユーザー上限10名・ストレージ5GB）/ Professional ¥20,000（100名・50GB）/ Enterprise ¥80,000（1,000名・500GB・SLA保証）。 | FR-010 |
| BR-MT-32 | Constraint | クレジットカード番号・CVV は TaskBoard のシステムに保存してはならない。Stripe のトークン（Payment Method ID）のみを保存する。 | FR-010, NFR-SEC-SEC |
| BR-MT-33 | Action Enabler | 月次課金の決済が失敗した場合: 失敗翌日・3日後・7日後にリトライする。7日後も失敗した場合、テナントステータスを `suspended` に変更し、テナント管理者に通知する。 | FR-010 |
| BR-MT-34 | Computation | プランアップグレード時の差額計算: 差額 = （新プラン月額 - 旧プラン月額）× 残日数 / 当月日数（Stripe の日割り計算に準拠）。 | FR-010 |
| BR-MT-35 | Constraint | Stripe からの Webhook リクエストは `Stripe-Signature` ヘッダーを検証し、署名が不正なリクエストは即座に拒否する（HTTP 400）。 | SRS SI-3, NFR-SEC-24 |

## 6. テナントライフサイクル・データ保持

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-40 | Constraint | テナントが解約した場合、テナントデータは解約日から 90 日間保持する。保持期間中はテナント管理者がデータをエクスポートできる。90 日経過後に DB・ストレージを物理削除する。 | FR-010 |
| BR-MT-41 | Constraint | 監査ログ（アクセスログ・変更ログ・セキュリティインシデントログ）は 2 年間保持しなければならない。改ざん防止のため Azure Monitor Logs の Immutable モードを使用する。 | FR-011, NFR-SEC-32 |
| BR-MT-42 | Action Enabler | テナントの物理削除が実行された場合: PostgreSQL DB インスタンス削除 → Blob コンテナ削除 → Key Vault シークレット削除 → Platform DB のテナントレコード論理削除（削除フラグを立て 5 年間保持）の順で実行する。各ステップの実行結果を削除監査ログに記録する。 | FR-010 |

## 7. API レート制限

| BR-ID | 分類 | ルール内容 | 関連要件 |
|-------|------|---------|---------|
| BR-MT-50 | Constraint | Azure API Management でのテナントごとのレート制限: Starter: 100 req/分 / Professional: 500 req/分 / Enterprise: 2,000 req/分。超過した場合は HTTP 429 を返却し `Retry-After` ヘッダーを付与する。 | FR-011 |
| BR-MT-51 | Constraint | レート制限はテナント単位で独立して適用する。テナント A がレート制限に達してもテナント B のリクエストはブロックしない（Noisy Neighbor 対策）。 | FR-011, NFR-AVL-06 |
